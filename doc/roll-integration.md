# Dice Roll in dice-rs

Dice Roll is the **only C runtime build**. The build script invokes the
`dice-roll-runtime` CMake target, archives only its objects into
`libdice.a`, then generates Rust bindings using the same generated header.

The built-in default `dice-rs/roll.dice` imports the standard Dice modules.
Projects with external event modules provide their own configuration:

```sh
export DICE_ROLL_CONFIG=/absolute/path/to/dice-extension/roll/craps.dice
export DICE_ROLL_IMPORT_PATHS=dice=/absolute/path/to/dice-extension/roll
export DICE_EXTENSION_DIRS=/absolute/path/to/dice-extension
export DICE_MODULES='fcntl;ioctl;poll;epoll;socket;stdio;unistd'
cargo build -p dice-rs --features 'dice dice-self dice-pthread_create dice-malloc'
```

The old legacy archive build path is removed. For `manual-link`, the caller
must provide `DICE_ROLL_HEADER` pointing to an existing generated header.

Both event and chain numeric values are generated by Dice Roll. C and Rust
use the same generated identifiers. Rust subscribers still use callback
registration; no static numeric IDs or old dispatcher are retained.

Record and replay require binaries using identical Roll configurations.
Older traces are not guaranteed compatible. The new path requires full build
and concurrency regression testing.
